# 과제 목표 설명 학습 기록

사용자 답변과 도우미의 보충 설명을 구분한다. 전체 목표의 최종 설명·재현 검토는 제출 전 다시 확인한다.

## 목표 1 — 절대 경로와 상대 경로

학습자는 상대 경로와 절대 경로의 이름을 구분했고, archive 안에서 cat notes.txt는 archive 안을 찾다가 실패한다고 설명했다. 도우미는 현재 위치 기준인 상대 경로와 / 시작점 기준인 절대 경로를 설명하고 ../notes.txt로 부모의 파일을 읽는 실습을 안내했다. 실제 문장이 나온다는 보고를 받았다. 전체 차이를 자기 말로 정리하는 최종 설명은 추후 보완한다.

## 목표 2 — 파일·디렉토리 권한과 숫자 표기

학습자는 소유자에게만 w가 있어 수정 가능함을 설명했고, rw-/r--/--- 조건을 640으로 정확히 구성했다. 755 폴더의 그룹은 읽기·진입만 가능하므로 새 파일을 만들 수 없다고 설명했다. 도우미는 폴더의 w가 항목 생성·삭제 등에 관여하고 기존 파일 내용 수정은 파일 권한과도 관련됨을 보충했다. [실제 실습 증거](../evidence/ch03/permissions.md).

## 목표 3 — 커스텀 이미지

NGINX 베이스에 HTML과 설정 템플릿을 COPY하고 1.0·2.0 이미지를 빌드했다. 파일 이름과 서비스 이름을 혼동해 Dockerfile을 나란히 보며 확인하고, HTML 저장만 한 경우와 재빌드·컨테이너 교체 후 화면을 비교했다.

학습자 설명: “카피로 넣은 html을 수정한 뒤에 화면에 반영하기 위해서는 새로 이미지를 빌드 하고 컨테이너도 새로 만들어야함. 명령어는 build와 compose를 씀”. COPY 이후 변경 반영 절차를 이해했다. [비교 실습](../evidence/ch06/copy-rebuild.md). 베이스 선택·각 커스텀 파일 목적의 최종 설명도 문서에 연결한다.

## 목표 4 — 포트 매핑

실제 포트 접속과 내부 통신을 실습했다. 내부 포트를 9090으로 바꿀 때 8082:8080 중 8080을 바꿔야 한다고 답했다. 전체 필요성에 대한 최종 자기 설명은 보완 대상이다. [환경 변수 검증](../evidence/ch08/environment.md).

## 목표 5 — 볼륨과 영속 데이터

컨테이너 삭제 후 새 컨테이너에 같은 볼륨을 연결해 메모가 표시됨을 보고했다. 다른 빈 볼륨에서는 이전 메모가 안 보이는 이유를 “워크샵데이터 볼륨에 저장되어있는거기 때문에”라고 설명했다. [검증 기록과 원문 증거 보완 항목](../evidence/ch07/volume.md).

## 목표 6 — Git과 GitHub

학습자 답변:

> 깃은 파일들을 관리하는 프로그램이고, 깃허브는 파일들을 저장할 수 있는 보관소 서비스다.

도우미 보충: Git은 내 컴퓨터에서 파일의 변경 이력을 관리하는 프로그램이다. GitHub는 파일과 Git 이력을 원격으로 보관·공유하고 협업하는 서비스다. 당시 첫·두 번째 커밋은 로컬 기록이었다. 이후 SSH push 성공과 제목 변경 커밋 bd7e9e1의 원격 반영을 확인했다. [로컬 실습](../evidence/ch04/git.md), [원격 연동](../evidence/ch04/github.md).
