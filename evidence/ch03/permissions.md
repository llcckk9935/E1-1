# 챕터 3 — 파일·디렉토리 권한

환경: Ubuntu Bash. 작업 흐름상 현재 위치는 workshop/archive이며 사용자 보고와 이전 실습에 근거한다. 사용자 이름과 개인 그룹 이름은 제출 기록에서 마스킹한다.

## 파일 권한 변경 전 — 실제 제공 출력

안내 명령:

```bash
ls -l ../notes.txt
```

학습자가 제공한 실제 출력:

```text
-rw-r--r-- 1 [USER] [GROUP] 35 Nov  4 12:45 ../notes.txt
```

일반 파일이며 소유자는 읽기·쓰기, 소유 그룹과 그 외 사용자는 읽기만 허용되는 권한으로 표시됐다. 이는 권한 비트의 해석이며 다른 계정으로 실제 접근한 실험은 아직 수행하지 않았다.

현재는 권한 표 읽기 학습 중이다. 파일 권한 변경·변경 후 비교, 디렉토리 권한 실험과 숫자 표기 설명은 아직 미수행이다.

## 권한 해석 이해도

학습자는 쓰기 권한 w가 소유자인 본인에게만 있기 때문에 다른 일반 사용자는 수정할 수 없다고 설명했다. 소유자와 다른 사용자 권한의 차이를 이해한 것으로 확인했다.

다음은 `chmod u-w ../notes.txt`로 소유자 쓰기 권한을 제거하고 `ls -l ../notes.txt`로 전후 표시를 비교하는 실습이다. 변경 결과는 아직 제공되지 않았다. 이후 실제 쓰기 동작 검증과 권한 복구를 진행할 예정이다.

## 파일 권한 변경 후 — 실제 제공 출력

chmod u-w 및 ls -l 안내 후 학습자가 제공한 출력이다. 사용자와 그룹 이름만 마스킹했다.

```text
-r--r--r-- 1 [USER] [GROUP] 35 Nov  4 12:45 ../notes.txt
```

변경 전 `-rw-r--r--`에서 변경 후 `-r--r--r--`로 소유자 쓰기 권한이 제거된 것을 확인했다. 다음은 append 리다이렉션으로 파일에 한 줄 추가를 시도해 쓰기 권한의 실제 동작을 검증한다. 아직 해당 결과는 받지 않았으며 권한 복구도 미수행이다.

## 쓰기 권한 제거 후 동작 검증 — 실제 제공 출력

안내 명령:

```bash
echo "권한 실험" >> ../notes.txt
```

처음 학습자가 권한 거부를 구두 보고했고, 이어 실제 오류를 제공했다.

```text
-bash: ../notes.txt: Permission denied
```

현재 사용자 소유 파일에서 쓰기 권한을 제거한 뒤 추가 요청이 거부되는 실제 동작을 확인했다. 다음은 chmod u+w로 쓰기 권한을 복구하고 같은 문장을 추가한 뒤 cat으로 읽는 실습이다. 아직 복구·추가 성공은 확인하지 않았다.

## 권한 복구 후 쓰기 동작 — 실제 제공 출력

chmod u+w, 같은 echo 추가 요청, cat 순서로 안내한 뒤 학습자가 아래 실제 cat 입력 줄과 출력을 제공했다. 사용자 이름과 컴퓨터 이름은 마스킹했다.

```text
[USER]@[HOST]:~/workshop/archive$ cat ../notes.txt
오늘 첫 파일을 만들었다.
권한 실험
```

기존 내용이 유지되고 추가 문장이 표시돼 복구 후 쓰기 동작 성공을 확인했다. chmod와 echo 입력 줄 자체는 미제공이며 cat 결과를 근거로 기록한다. 파일 권한의 변경 전후 표시, 쓰기 거부, 복구 후 쓰기 성공까지 증거를 확보했다. 다음 단위는 ls -ld .으로 현재 archive 디렉토리 자체 권한 확인이다. 디렉토리 변경 실험과 숫자 표기 설명은 아직 남아 있다.

## 디렉토리 권한 변경 전 — 실제 제공 출력

`ls -ld .` 안내 후 제공받은 출력이다. 소유자와 그룹 이름은 마스킹했다.

```text
drwxr-xr-x 2 [USER] [GROUP] 4096 Nov  4 15:12 .
```

앞의 d는 디렉토리를 의미한다. 소유자는 rwx, 그룹과 그 외 사용자는 r-x 권한이다. 디렉토리 r은 항목 이름 목록 읽기, w는 내부 항목 생성·삭제 등에 관여하며 보통 x와 함께 필요하고, x는 경로 탐색·진입을 허용한다.

다음 실습은 workshop으로 나가 archive의 소유자 x 권한을 제거하고 cd archive로 진입을 시도하는 것이다. 현재 archive 밖에서 권한을 조작하도록 하여 복구 경로를 확보한다. 실제 변경·진입 거부·복구 결과는 아직 대기 중이다.

## 디렉토리 x 제거 후 진입 검증 — 실제 제공 오류

안내한 명령 순서:

```bash
cd ..
chmod u-x archive
cd archive
```

학습자가 제공한 실제 오류:

```text
-bash: cd: archive: Permission denied
```

소유자의 x를 제거한 뒤 진입이 거부되는 동작을 확인했다. 마지막 cd가 실패했으므로 안내 순서대로 실행했다면 현재 위치는 workshop이다. 다음은 그 위치에서 ls -ld archive로 변경 후 권한을 확인하며, 복구는 그 뒤에 진행한다. 그룹·그 외 사용자의 x가 남아 있더라도 소유자에게 해당하는 권한이 우선 적용되는 사례다.

## 디렉토리 권한 변경 후 — 실제 제공 출력

`ls -ld archive` 안내 후 제공받은 출력이다. 소유자와 그룹 이름을 마스킹했다.

```text
drw-r-xr-x 2 [USER] [GROUP] 4096 Nov  4 15:12 archive
```

변경 전 drwxr-xr-x에서 변경 후 drw-r-xr-x로 소유자의 x만 제거됐음을 확인했다. 다음은 workshop에서 chmod u+x archive로 복구한 뒤 cd archive로 진입하는 실습이다. 복구 후 진입 결과는 아직 제공되지 않았다.

## 디렉토리 진입 권한 복구 — 학습자 보고

chmod u+x archive 및 cd archive 안내 후 학습자는 “+ 해서 들어 갔어”라고 보고했다. 소유자 진입 권한 복구 후 실제 진입 성공을 확인한 보고로 기록한다. 프롬프트와 복구 후 ls 출력 원문은 미제공이며 생성하지 않는다.

파일과 디렉토리 각각 변경 전후 권한 표시 및 동작 비교를 학습했다. 다음은 r=4, w=2, x=1 합산과 소유자·그룹·그 외 사용자 순서로 644·755를 해석하는 학습이다. 숫자 표기 이해도와 예시 명령의 실제 실행은 아직 미확인이다.

## 숫자 표기 이해도

r=4, w=2, x=1의 합산과 세 자리 순서를 설명하고 644·755의 예시를 제공했다. 소유자 읽기·쓰기, 그룹 읽기, 그 외 권한 없음 조건을 제시하자 학습자는 `640`이라고 정확히 답했다.

다음은 archive에서 `chmod 640 ../notes.txt`와 `ls -l ../notes.txt`로 숫자 설정을 실제 적용·확인하는 것이다. 아직 실행 결과는 제공되지 않았다.

## 숫자 권한 적용 — 실제 제공 출력

chmod 640 및 ls -l 안내 후 학습자가 제공한 출력이다. 소유자와 그룹 이름은 마스킹했다.

```text
-rw-r----- 1 [USER] [GROUP] 49 Nov  5 08:05 ../notes.txt
```

권한이 소유자 rw-, 그룹 r--, 그 외 ---로 표시돼 640 적용 결과와 일치했다. 파일 내용은 앞선 쓰기 실험 후의 상태이며 현재 권한은 640으로 유지한다. 이 결과를 다른 계정의 실제 접근 시험까지 수행한 것으로 확대하지 않는다.

다음은 755 폴더의 그룹 사용자에게 새 파일 생성이 허용되는지 설명하는 챕터 정리 질문이다. 이 질문에서는 일반 권한 비트와 부모 경로 접근 조건을 가정하며 별도의 ACL·권한 상승 같은 예외는 현재 학습 범위에 넣지 않는다. 학습자 답변은 아직 대기 중이다.

## 챕터 정리 설명

학습자는 그룹 사용자는 읽기·실행만 가능하므로 새 파일을 만들 수 없다고 설명했다. 755의 그룹 권한 r-x에 w가 없음을 근거로 디렉토리 항목 생성 여부를 판단한 것을 확인했다. 폴더의 w는 항목 생성·삭제 등이고 기존 파일 내용 수정은 해당 파일의 권한과도 관련된다는 구분을 보충 설명한다.

권한 챕터의 핵심 학습은 파일/디렉토리 변경 전후, 동작 거부·복구, 숫자 640 적용과 755 해석까지 진행했다. 제출용 명령 입력·일부 실행 보고의 원문 보완, 최종 설명 검토는 도우미가 별도 관리한다. 다음 학습은 챕터 4 Git이며 우분투 내부의 Git 버전 확인부터 진행한다.
