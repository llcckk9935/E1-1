# 기본 CLI 학습 기록

환경: WSL Ubuntu, Bash. 설치 진단을 잠시 멈추고 기본 명령을 직접 구성하는 실습을 진행했다. Docker 연결의 미해결 상태는 기존 환경 기록과 학습계획에서 유지한다.

## 폴더 생성·조회·이동

다음은 학습자가 대화에서 구성한 명령과 실행 보고다. 터미널 원문이 제공되지 않은 부분에 출력이나 프롬프트를 만들어 넣지 않는다.

| 작업 | 명령 | 실제 확인 범위 |
|---|---|---|
| 홈으로 이동할 명령 구성 | `cd ~` | 학습자가 명령을 정확히 답함. 이번 복습의 실행 원문은 미제공이며 앞선 챕터 1에는 실제 실행 증거가 있음 |
| 폴더 생성 | `mkdir workshop` | 학습자가 명령을 구성하고 실행했다고 보고 |
| 생성 결과 확인 | `ls` | 학습자가 목록에 workshop이 보인다고 보고 |
| 폴더 내부 이동 | `cd workshop` | 학습자가 명령을 구성하고 프롬프트 경로가 ~/workshop으로 바뀌었다고 보고 |

위 기록은 학습 진도 확인이다. 원본의 명령과 실제 출력이 함께 있는 제출 증거는 최종 정리 때 별도 확보한다. 챕터 2의 다른 필수 조작과 경로 설명 목표가 모두 완료된 것은 아니다.

## 빈 파일 생성과 목록 확인

학습자는 처음 `tocuh notes.txt`라고 명령을 작성했다. 도우미가 touch로 철자를 수정하도록 안내했고 학습자가 실행 완료를 보고했다. 실제 오류 출력은 제공되지 않았으므로 Command not found 같은 출력을 만들어 기록하지 않는다.

학습자는 목록 확인 명령을 `ls`라고 직접 답했고 notes.txt가 보인다고 보고했다. 빈 파일 생성·존재 확인은 학습자 보고로 확인했으며 파일 크기·내용은 아직 직접 출력으로 검증하지 않았다.

## 파일 내용 확인·저장·재확인

학습자는 cat으로 빈 notes.txt를 읽은 뒤 아무 내용도 나오지 않는다고 보고했다. 빈 파일에는 출력할 내용이 없음을 설명했다.

학습자가 직접 구성한 명령:

```bash
echo "오늘 첫 파일을 만들었다." > notes.txt
```

echo의 출력과 `>`의 파일 저장(기존 내용 덮어쓰기)을 설명했다. 저장 명령 실행 시 화면에 아무것도 나오지 않은 점을 질문해, 화면 출력이 파일로 전달되기 때문이라고 설명했다.

후속 확인 명령은 `cat notes.txt`이며 학습자는 아까 저장한 내용이 나온다고 보고했다. 실제 출력 문장은 직접 붙여 넣지 않았으므로 성공 로그로 재구성하지 않는다. 문장 저장과 읽기 확인은 학습자 보고로 기록한다.

## 파일 복사와 내용 확인

학습자는 처음 `cp notes.txt`만으로 안 된다고 질문했다. 오류 출력은 제공되지 않았으므로 만들어 기록하지 않는다. 원본과 목적지가 필요함을 설명한 뒤 완성 예시를 제공했다.

```bash
cp notes.txt backup.txt
```

학습자는 실행했다고 보고했다. 후속으로 `cat backup.txt`를 안내했고 저장한 문장이 나온다고 보고했다. 실행·내용 일치는 학습자 보고이며 실제 출력 원문은 미제공이다.

학습 방식 조정: 처음 배우는 명령은 완성 예시 → 각 부분 의미 → 직접 사용 → 작은 응용 순서로 설명한다. 문법을 배우기 전에 명령을 추측하도록 요구하지 않는다.

## 파일 이름 변경

`mv backup.txt copy.txt`로 파일 이름을 변경하고 ls로 확인하도록 안내했다. 이후 학습자는 “된다”라고 보고했다. 명령 줄·목록 출력 원문은 미제공이므로 구체적인 ls 결과를 만들어 기록하지 않는다.

## 다른 폴더로 파일 이동

`mkdir archive` 안내 후 학습자는 폴더를 만들었다고 보고했다. 이어 아래 명령으로 파일을 옮기고 목적지 목록을 확인하도록 안내했다.

```bash
mv copy.txt archive/
ls archive
```

학습자는 옮긴 것까지 확인했다고 보고했다. 실제 명령 줄과 목록 원문은 미제공이므로 학습자 실행·확인 보고로 기록한다. mv의 이름 변경과 디렉토리 이동을 각각 학습했다.

다음으로 연습용 복사본 archive/copy.txt 삭제와 ls archive로 결과 확인을 안내했다. notes.txt 원본은 삭제 대상으로 지정하지 않았다.

## 삭제 확인 중 경로 오류 — 진단 중

학습자가 제공한 실제 오류:

```text
ls: cannot access 'archive': No such file or directory
```

현재 위치에서 archive를 찾지 못한 결과이며 rm의 실제 실행 여부·대상·성공은 아직 확인하지 않았다. 사용자의 현재 위치가 workshop이 아닌 경우 등을 가설로 두고, 먼저 이미 배운 pwd로 현재 위치를 확인한다. archive 폴더가 삭제됐다고 단정하거나 즉시 다시 만들지 않는다.

### 원인 확인과 경로 수정

학습자는 cd ~로 홈에 이동한 뒤 실행했기 때문이라고 설명하고, workshop으로 돌아와 다시 실행하니 된다고 보고했다. pwd 출력은 별도로 제공하지 않았다. 상대 경로 archive는 현재 위치를 기준으로 해석되므로 홈에서는 홈/archive를 찾고, workshop에서는 홈/workshop/archive를 찾는다는 원리와 일치한다.

경로 오류가 해소됐다는 보고는 확인했으나 ls archive 결과가 빈 목록인지 copy.txt가 남아 있는지는 아직 미확인이다. 따라서 파일 삭제 성공은 그 결과를 확인한 뒤 기록한다. 다음은 현재 목록에서 copy.txt 존재 여부 확인이다.

### 삭제 결과 확인

학습자는 workshop에서 ls archive 실행 결과 아무것도 나오지 않는다고 보고했다. 파일 이동 전후의 앞선 실행 보고와 함께 연습용 copy.txt 삭제 후 일반 목록에 표시되지 않는 것을 확인했다. archive 디렉토리는 조회 가능하므로 폴더 삭제로 기록하지 않는다. 아직 ls -a로 숨김 항목까지 확인한 것은 아니므로 “어떠한 숨김 항목도 없는 완전한 빈 디렉토리”까지 증명했다고 확대하지 않는다.

삭제 학습과 상대 경로 오류 해결을 기록했으며 다음 단위는 workshop에서 ls -a로 숨김 항목 포함 목록 확인이다.

## 숨김 항목 포함 목록 확인 — 실제 제공 출력

workshop에서 `ls -a` 안내 후 학습자가 제공한 출력:

```text
.  ..  archive  notes.txt
```

`.`(현재 디렉토리), `..`(부모 디렉토리) 및 archive·notes.txt가 표시됐다. 사용자 생성 숨김 파일이 있다고 기록하지 않는다. 기본 ls와 -a 옵션의 차이를 설명했다.

학습자는 `cd ..` 안내 후 홈으로 왔다고 보고했다. workshop의 부모 디렉토리로 이동한 결과를 확인했다. 프롬프트 원문은 제공되지 않았으므로 보고로 구분한다.

우분투 홈에서 workshop으로 사용자 계정에 맞는 절대 경로를 사용해 이동하도록 안내했고 학습자는 완료했다고 보고했다. 프롬프트 원문은 미제공이므로 실행 보고로 기록한다. 경로의 사용자 이름은 제출 문서에서 마스킹한다.

다음은 과제 목표 1의 설명 확인이다. 상대 경로 `cd workshop`과 절대 경로 `cd /home/[USER]/workshop`의 기준 차이를 학습자가 자기 말로 설명한다. 아직 답변은 받지 않았다.

## 절대·상대 경로의 사용 상황 설명

학습자는 두 경로의 이름은 구분했으나 차이와 필요성을 질문했다. 앞선 홈에서 ls archive가 실패했던 사례를 사용해 기준 위치를 설명했다.

학습자는 archive 안에서 cat notes.txt를 실행하면 archive 안을 찾고 파일이 없으므로 실패한다고 정확히 답했다. 이어 절대 경로를 써야 한다고 말해, 절대 경로뿐 아니라 상대 경로 `../notes.txt`로 부모 폴더의 파일을 지정할 수도 있음을 설명했다.

다음 실습은 workshop에서 archive로 들어간 뒤 `cat ../notes.txt`로 부모 폴더의 파일을 읽는 것이다. 아직 실제 결과는 받지 않았다.

### 부모 경로 읽기 실행 확인

`cd archive` 후 `cat ../notes.txt` 안내에 대해 학습자는 저장한 문장이 나온다고 보고했다. 현재 위치는 archive로 보고된 흐름이며 부모 폴더의 파일을 경로로 지정해 읽는 실습을 수행했다. 실제 출력 문장은 제공되지 않았으므로 터미널 원문으로 재구성하지 않는다.

기본 파일·디렉토리 조작 학습을 바탕으로 다음은 챕터 3의 파일 권한 조회를 진행한다. 챕터 2의 제출용 명령·출력 증거 정리와 최종 설명 검토는 도우미 관리 항목으로 남긴다. 챕터 2를 제출 검증까지 모두 완료했다고 표시하지 않는다.
