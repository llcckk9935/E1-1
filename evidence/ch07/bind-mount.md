# 바인드 마운트 검증

원본 필수: 실행 명령과 호스트 파일 변경 전후를 비교하여 컨테이너에 반영되는지 확인한다.

현재는 준비 단계다. Dockerfile COPY는 빌드 시점에 파일을 이미지에 포함한다. 이번 실습은 WSL Ubuntu의 실제 폴더를 컨테이너 웹 폴더에 연결한다. 파일 변경 반영과 컨테이너 삭제 후 볼륨 영속성은 별도로 검증한다.

첫 작업은 기존 ~/workshop/web에 이동해 index.html 실제 원문을 cat으로 확인하는 것이다. my-web이 8080을 사용하므로 새 마운트 실습은 다른 이름과 포트로 만들 예정이다. 아직 새 실행·마운트·파일 변경·브라우저 전후 비교는 수행하지 않았다.

## 변경 전 호스트 파일 — 실제 제공 원문

cd ~/workshop/web 및 cat index.html 안내 후 학습자가 제공한 내용:

```html
<meta charset='utf-8'><h1>내 개발 작업실</h1>
```

학습자가 실제로 확인한 HTML과 앞서 확인한 Dockerfile을 제출 작업 공간의 [web/index.html](../../web/index.html), [web/Dockerfile](../../web/Dockerfile)에 같은 내용으로 보관했다. 실제 빌드·실행은 사용자 WSL에서 수행된 것이며 이 Windows 작업 공간에서 다시 빌드했다고 기록하지 않는다. 이후 WSL 파일이 바뀌면 실제 출력 확인 후 이 사본도 맞춘다.

다음은 web-live라는 새 컨테이너에 호스트 /home/llcckk/workshop/web을 컨테이너 /usr/share/nginx/html로 바인드 마운트하는 단계다. 포트는 8081:80을 사용하여 기존 8080의 my-web과 구분한다. 아직 컨테이너 생성·연결·응답·수정 전후 검증 결과는 받지 않았다.

## 바인드 마운트 실행 요청 — 실제 제공 ID

안내 명령:

```bash
docker run -d --name web-live -p 8081:80 -v /home/llcckk/workshop/web:/usr/share/nginx/html workshop-web:1.0
```

학습자가 제공한 반환 ID:

```text
515bc5c495a33bab8c0a841abc3d8e19d99bb491f2b0c899e9c2cb7471e8855f
```

새 컨테이너 식별자가 반환됐다. 아직 실제 서버 응답·마운트 정보 조회·변경 반영은 검증 전이다. 다음은 Windows 브라우저에서 http://localhost:8081의 수정 전 제목을 확인하는 것이다.

## 수정 전 브라우저 응답 — 학습자 보고

localhost:8081에서 “내 개발 작업실”이 보이는지 확인하도록 안내했고 학습자가 그렇다고 응답했다. 화면 이미지나 HTTP 원문은 아직 미제공이며 접속 성공 보고로 구분한다.

다음은 WSL의 ~/workshop/web/index.html 제목을 “바인드 마운트로 바꾼 화면”으로 수정하고 같은 8081 페이지를 새로고침하는 것이다. 이 사이에 docker build·새 run은 안내하지 않는다. 실제 변경 후 소스와 화면은 아직 확인하지 않았다.

## 호스트 파일 수정 후 반영 — 학습자 보고

실행하도록 안내한 명령:

```bash
echo "<meta charset='utf-8'><h1>바인드 마운트로 바꾼 화면</h1>" > ~/workshop/web/index.html
```

localhost:8081을 새로고침하도록 안내했고 학습자는 화면에 “바인드 마운트로 바꾼 화면”이 나온다고 보고했다. 사이에 이미지 재빌드나 새 컨테이너 실행을 안내·보고받지 않았다. 변경 전 “내 개발 작업실”에서 변경 후 문구로 바뀐 관찰을 기록한다. 화면 파일과 수정 후 HTML의 cat 원문은 아직 미제공이다.

다음은 바인드 마운트 없이 앞서 COPY로 만든 이미지를 실행한 localhost:8080의 제목과 비교하는 실습이다. 8080의 이번 응답은 아직 확인하지 않았다. 제출용 web 소스 사본의 바이트 단위 동기화는 수정 후 원문 확인 때 수행한다.

## COPY 기반 서버와 비교 — 학습자 보고

localhost:8080을 열고 새로고침하도록 안내한 뒤 학습자는 “내 개발 작업실”이 나온다고 보고했다.

| 주소 | 구성 | 호스트 파일 수정 후 보고된 제목 |
|---|---|---|
| localhost:8080 | 빌드 때 COPY한 이미지의 파일 사용 | 내 개발 작업실 |
| localhost:8081 | 호스트 web 폴더 바인드 마운트 | 바인드 마운트로 바꾼 화면 |

원본 파일 수정이 이미 만들어진 이미지의 COPY 결과를 자동 변경하지 않는 반면, 연결한 호스트 폴더를 사용하는 컨테이너에는 반영되는 차이를 관찰했다. 표는 실제 브라우저 화면 파일이 아니라 학습자의 접속 결과 보고를 정리한 것이다. 다음은 이 차이를 학습자가 자기 말로 설명하는 확인이다.
